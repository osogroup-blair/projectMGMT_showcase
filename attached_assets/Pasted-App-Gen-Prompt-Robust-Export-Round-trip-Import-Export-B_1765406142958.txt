App Gen Prompt – Robust Export (Round-trip Import/Export)

Build a “Data Export” feature for my project management system.
The domain model is:

Projects

Deliverables (children of Projects)

Epics (children of Deliverables)

Stages (global stage definitions)

EpicStages (junction between Epics and Stages; sequence of an epic through stages)

Tasks (children of Epics/EpicStages, ultimately under a Project)

Milestones (tied to Projects, and optionally to EpicStages and/or Tasks)

Plus supporting config entities: Users, ProjectRoles, ProjectRoleAssignments, SavedViews, StageViewConfigs, GuidanceItems, StageTemplates, MappingTemplates, RoleTemplates.

Goal

Implement a robust export that:

Produces a single XLSX workbook with one sheet per entity.

Each sheet contains all attributes for that entity (no fields are omitted).

Relationships between entities are expressed strictly through IDs and foreign key columns across sheets.

The exported workbook schema is round-trippable: the exact same structure can be used as input for an import endpoint to recreate or update the data.

The export should contain all data necessary to power all existing views we’ve defined (projects list, project overview, task board, stage workspace, milestones, roles/assignments, saved views, guidance, etc.).

UX Requirements

Create a “Data Export” page at route /projects/:projectId/export.

The page should:

Show the current project header (name, client, status).

Let the user choose scope:

“This project only” (default).

“All projects” (admin only).

Let the user choose format:

XLSX (primary) – multi-sheet workbook.

Optionally CSV (one zip with multiple CSV files) – not required, but if easy, include.

Options for include configuration data (SavedViews, StageViewConfigs, Roles, RoleAssignments, Guidance, Templates, etc.). Default ON.

Show a summary of the workbook schema (sheet names and key foreign keys).

Provide a primary “Export” button that triggers the export and downloads the workbook.

Provide a secondary “Download Template Only” button that generates an empty workbook with correct sheets/columns but no data (for import templates).

API + Backend Requirements

Implement an endpoint like:

GET /api/export?scope=project&project_id={id}

GET /api/export?scope=all

The endpoint should:

Load all entities required for the scope.

Populate a workbook with one sheet per entity as defined in the schema below.

Ensure column order is deterministic and stable over time.

Serialize IDs as strings consistently across all sheets.

Also add an import endpoint that accepts the same workbook:

POST /api/import (multipart upload).

It should parse each sheet, respect IDs and foreign keys, and upsert records:

If id exists → update.

If id is blank → create new (where allowed).

Validation rules:

Fail fast on missing required foreign keys (e.g., Deliverable.project_id that doesn’t match any Projects.id in the workbook or DB).

Provide a clear summary of errors per sheet and row.

Relationship & Integrity Rules

All foreign key columns (*_id) should reference the id column of the corresponding sheet.

The export should be self-contained: if exporting a project, include all related rows from the other sheets that belong to that project.

When importing:

Respect sheet-level order: Projects → Deliverables → Epics → Stages → EpicStages → Tasks → Milestones → Config tables.

Validate referential integrity and report any missing dependencies with clear sheet name + row index.

Ensure the schema is stable: subsequent exports of the same project should produce columns in the same order, so that external tooling and templates do not break.

Performance & DX

The export endpoint should be efficient for projects with thousands of tasks. Use streaming or chunking where supported.

Provide meaningful progress/“Export in progress” feedback on the UI if the App Gen tool supports it.

Document the workbook schema in the UI (e.g., expandable “Schema” section that lists sheets and key columns) so users understand how to edit and re-import.
