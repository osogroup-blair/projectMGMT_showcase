# Prompt: Design & Plan Microsoft Outlook (Microsoft Account) Sign-In / Sign-Up with Admin-Controlled Toggle

You are an expert product architect and systems designer.  
Your task is to create a **clear, detailed plan** to enable users to **sign up and sign in using their Microsoft Outlook / Microsoft account email**.

This feature must be **optional and admin-controlled**, not hard-coded.

---

## Objective
Design a system that allows:
- End users to sign up and sign in using their **Microsoft account (Outlook, Office 365, Microsoft Entra ID)**
- Admins to **enable or disable Microsoft sign-in** via a simple GUI toggle
- Secure, controlled access using **SSO-style authentication**
- Safe rollout and clear failure handling

The goal is a **clean MVP** that can expand later to enterprise SSO scenarios.

---

## Functional Requirements

### 1. End-User Experience
- Users see a **“Continue with Microsoft”** button on:
  - Sign-up
  - Sign-in
- If disabled by admins:
  - The button does not appear
  - Existing Microsoft users are informed gracefully
- Support:
  - New user sign-up
  - Existing user sign-in
  - Account linking if email already exists

---

### 2. Admin Configuration (GUI Required)
Design an **Admin Settings UI** that includes:
- A toggle:
  - `Enable Microsoft Sign-In`
- When ON:
  - Microsoft sign-in button appears for users
  - Admin can configure allowed access rules
- When OFF:
  - Microsoft sign-in is hidden
  - No new Microsoft sign-ins allowed
  - Existing users retain access via alternative login methods

Admin configuration should clearly show:
- Status (Enabled / Disabled)
- Who last changed the setting
- Validation state (configured correctly or not)

---

### 3. Access Control & SSO Behavior
Define how access is granted once Microsoft authentication succeeds:
- Allowed email domains (optional but recommended)
- Whether users are:
  - Auto-created
  - Auto-joined to an organization
  - Required to complete onboarding
- Support **single sign-on behavior**:
  - Session reuse
  - Secure token handling
  - Logout propagation (where applicable)

---

### 4. Account Mapping & Identity Rules
Define rules for:
- Mapping Microsoft email → internal user account
- Handling:
  - First-time sign-ups
  - Existing users with matching email
  - Conflicting or duplicate emails
- Linking Microsoft login to an existing account safely

---

### 5. Security & Compliance Expectations
Plan for:
- Secure token exchange and storage
- Minimal data access (email, name, profile image only)
- Clear audit logs for:
  - Admin changes
  - Sign-in events
- Error handling for:
  - Revoked access
  - Expired credentials
  - Misconfiguration

---

## UX & UI Requirements

### User-Facing
- Clear Microsoft sign-in button
- Loading and error states
- Friendly messaging if sign-in is disabled or fails

### Admin-Facing
- Simple toggle control
- Inline validation
- Clear instructions and status indicators
- No technical jargon required for setup

---

## Implementation Plan (What, Not How)
Describe:
1. Authentication flow from click → access granted
2. Admin toggle behavior and enforcement points
3. Data required to store configuration and account links
4. How sign-up and sign-in differ
5. Rollout strategy (disabled by default)
6. Fallbacks if Microsoft sign-in is unavailable

Avoid naming specific libraries or platforms—focus on **system behavior and responsibilities**.

---

## Acceptance Criteria
Write clear **Given / When / Then** acceptance criteria for:
- Enabling Microsoft sign-in
- Signing up with a Microsoft account
- Signing in with an existing account
- Disabling Microsoft sign-in
- Handling errors and edge cases

---

## Output Format
Return the plan as:
1. Feature overview
2. User flows
3. Admin flows
4. Configuration & access rules
5. Security considerations
6. Implementation steps
7. Acceptance criteria
8. Open questions / future enhancements

Proceed by creating the full, detailed plan now.
