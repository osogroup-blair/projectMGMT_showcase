CONSOLIDATION RULES (IMPORTANT)
A) Consolidate many current “project-*” pages into ONE Project Workspace:
- Create a single route container page: pages/project/index.tsx
- It will render subviews/tabs/routes for:
  overview, management, settings, team, roles/assignments, deliverables + detail, epic detail,
  milestones + overview, sprints list + detail, saved views,
  stages (designer/workspace/view settings), tasks board + detail, timeline
- Those subviews should live in features/project/*, not as top-level pages.

B) Project Wizard becomes “project-new”:
- Move current project-wizard page to pages/project-new/index.tsx
- Wizard internals (step components, state, validation) should live under features/project (or features/projectWizard if needed).

C) Import/Export becomes Project Tools:
- Consolidate project-import, preview, mapping, and export into pages/project-tools/index.tsx
- Internal components live under features/project/tools/* (or features/project/* if you prefer).

D) Global vs Feature ownership:
- Keep global UI primitives in client/src/components/ui/*
- Keep global layout in client/src/components/layout/*
- EVERYTHING else that is feature-specific should move to client/src/features/<feature>/*
- Avoid “components/project/*” and “pages/*.tsx” sprawl.

MAPPING GUIDELINES (HIGH LEVEL)
- client/src/pages/*.tsx -> consolidate into the fewer pages listed above
- client/src/components/home/* -> features/home/*
- client/src/components/project/* -> features/project/*
- client/src/components/task/* -> features/tasks/* (or features/project/tasks/* if project-scoped)
- client/src/components/admin/* -> features/templates/* or features/admin/* (choose ownership based on usage)
- client/src/contexts/* -> client/src/context/*
- Keep shared/schema.ts unchanged as the domain schema source of truth.
