## 0) Feature Summary (Read Carefully)

### Core behavior
The system manages a hierarchy of timeline constraints:

- **Task** has due date (and optionally start date)
- **Epic** has a date range (start/end)
- **Deliverable** has a date range (start/end)

Rules:
1. If a **child** (Task) changes and becomes **outside the parent range** (Epic), the system must **warn the user** before applying any cascading changes.
2. If the user confirms cascading changes, the parent range should expand/shift to include the child.
3. If that change pushes the parent (Epic) outside of its parent (Deliverable), the system should optionally cascade again (with a single aggregated warning where possible).
4. Users must be given a prompt before changes occur, with 3 options:
   - **Option A:** “Make the change and auto-sync (apply cascading repercussions)”
   - **Option B:** “Make the change but DO NOT auto-sync (save with an out-of-range flag)”
   - **Option C:** “Cancel and go back (do not save)”

### Non-goals / Guardrails
- No silent cascading changes.
- No hidden range violations: any out-of-range condition must be visible via flags and surfaced to users/admins.
- Service must be triggerable by the app and safe under concurrency.

## 2) Domain Definitions (Use These Terms)

### Entities
- **Deliverable**: top-level time box; has `start_date`, `end_date`
- **Epic**: mid-level time box; has `start_date`, `end_date`, belongs to Deliverable
- **Task**: atomic work item; has `due_date` (and optionally `start_date`), belongs to Epic
- **Hierarchy Path**: Task → Epic → Deliverable (at minimum)

### “In Range” meaning
A child date is in range if it falls within inclusive boundaries of the parent:
- For Task due_date: `epic.start_date <= task.due_date <= epic.end_date`
- For Epic range: `deliverable.start_date <= epic.start_date AND epic.end_date <= deliverable.end_date`

### “Repercussions”
Potential repercussions include:
- Expanding date ranges upward (Epic, then Deliverable)
- Updating derived timeline summaries and sprint planning artifacts (if applicable)
- Triggering notifications and audit log entries
- Changing status of “Schedule Health” indicators
