- Pressing Enter in an epic input creates a new epic input row immediately.

  Option A: sticky top action bar

4) Custom Implementation Framework + Editable Template Tasks
- User can choose:
  a) “No stages yet” (create project first)
  b) “Use template framework”
  c) “Custom framework” (create stages from scratch)
- For each stage, user can define default tasks that are either:
  - created once per project stage (stage-level tasks)
  - created per epic (epic-scoped tasks repeated for each epic)
- Template tasks must be placeholders and editable before apply:
  - edit title, description, type/scope (per-epic vs once), estimates/dates if present, assignee role, status
  - allow add custom tasks
  - allow remove tasks
- IMPORTANT: Changes in wizard should NOT mutate the global template definitions unless explicitly saved in admin templates.
  These are “project-scoped overrides” applied during project creation only.

5) Role-based assignee filtering (requires template/user management work)
- When selecting a user for a role (or selecting assignee for tasks by role), filter the user list to only people eligible for that role.
- This requires a mapping table + (optional) permission matrix:
  - Role types (existing or new): e.g., PM, Engineer, Designer, QA, etc.
  - User ↔ Role eligibility mapping
- Update templates so tasks can specify “assignee_role_type_id” (or similar) and during wizard assignment the dropdown filters accordingly.
- If no mapping exists, show “No eligible users” and allow admin fallback or manual override (define which behavior).

6) Fix notifications triggered after creation (task storm)
- When creating a project that generates many entities (hundreds of tasks), avoid firing a notification per entity.
- Replace with a batched summary notification:
  - “Project created: X stages, Y epics, Z tasks created”
- Ensure the UI still gets progress/confirmation without spamming.
