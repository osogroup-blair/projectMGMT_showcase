You are designing and implementing a UI theming enhancement for a SaaS project management application.

## Feature Name
Contextual Section Accent Panels

## Objective
Add a subtle but clear colored border accent to primary container panels on overview pages to visually communicate **what core object the user is currently viewing**, while also supporting a **user-centric dashboard context**.

The accent system must clearly distinguish between:
- Object-centric views (Project, Deliverable, Epic, etc.)
- User-centric views (My Dashboard, My Work, Personal Overview)

---

## Scope

### Object-Centric Pages
- Project
- Deliverables
- Epics
- Tasks
- Stages
- Milestones
- Sprints
- Admin

### User-Centric Pages
- User Dashboard
- “My Work”
- Personal Overview / Home

---

## Design Rules

### 1. Accent Purpose
- Exactly **one accent color** is active per page.
- Object-centric pages use the **object’s semantic color**.
- User-centric pages use a **User Accent color**, representing personal ownership and focus.
- Accents are informational, not interactive.

---

### 2. Visual Treatment
- Accent appears as a **border rail** on the primary container panel(s).
- Preferred placement:
  - Left border (default)
  - Top border (acceptable alternative)
- Border thickness:
  - Desktop: 3–4px
  - Mobile: 2–3px
- Corners must respect global border radius.
- Solid color only (no gradients).

---

### 3. Color Token Mapping

#### Object Semantic Tokens
- Project → `--color-project`
- Deliverable → `--color-deliverable`
- Epic → `--color-epic`
- Task → `--color-task`
- Stage → `--color-stage`
- Milestone → `--color-milestone`
- Sprint → `--color-sprint`
- Admin → `--color-admin`

#### User-Centric Token
- User Dashboard / My Work → `--color-user`

The **User color** must:
- Be distinct from all object colors
- Feel neutral, calm, and personal (not status-driven)
- Work as a “home base” color across sessions

All tokens must support light and dark mode.

---

### 4. Component Behavior
- Accents are applied via a shared container component
  (e.g. `ContextPanel`, `OverviewPanel`)
- Component accepts a `contextType` prop:
  - `project | deliverable | epic | task | … | user`
- Color resolution is automatic via theme tokens.
- Pages must never hardcode color values.

---

### 5. Hierarchy & Overrides
- User-centric pages always use the **User accent**, even if they display mixed objects.
- Object-centric pages never inherit the User accent.
- Nested content does not override the page’s primary accent.

---

### 6. Accessibility & Quality
- Accent colors must meet contrast requirements.
- UI remains fully usable without color.
- Do not rely on accent color for critical state or errors.

---

## Non-Goals
- No status indication
- No text color changes
- No per-user customization (future enhancement)

---

## Deliverables
- Updated shared container component
- Object + User color token mapping
- Light and dark mode support
- Example implementations:
  - User Dashboard
  - Project Overview
  - Deliverable Overview

---

## Success Criteria
- Users instantly know whether they are in **“my space”** or **“object space”**
- The UI feels calmer, clearer, and more intentional
- The system scales cleanly as new domains are added
