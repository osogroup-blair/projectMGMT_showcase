# Prompt: Define MVP “Team Overview / Management” Page by Analyzing the Current Codebase

You are an expert product engineer and systems analyst. Your job is to **search the current codebase** and produce a concrete MVP plan for a **Project Team Overview / Management** page.

## Objective
Create an MVP feature that lets a project clearly define and manage:
1) **Project Owner** (single accountable person)
2) **Stakeholders** (people who follow/approve, not necessarily doing tasks)
3) **Team Members** (people who do the work)

The project also needs **Project Roles** that can be assigned to tasks. When tasks have an “assigned role,” the system should be able to:
- detect whether tasks currently store a role assignment
- map task-role → team member(s) who can fulfill that role
- prefill or recommend an assignee when creating/importing tasks

Your output must be grounded in what already exists in the codebase (models, DB schema, APIs, UI routes, components, permissions).

---

## Step 1 — Codebase Discovery (Search & Inventory)
Search the codebase to identify existing implementations for:
- Project model/entity fields (look for: `owner`, `stakeholders`, `members`, `team`, `users`)
- Membership tables/relationships (project_user, project_members, etc.)
- Role system (global roles vs project roles vs task roles)
- Task schema fields (look for: `assignee`, `assignedRole`, `roleId`, `requiredRole`, `roleType`)
- Existing pages/routes related to project settings, people, access, permissions
- Existing UI components that can be reused (user picker, role picker, table/list cards, avatars, etc.)
- Any permissions or RBAC/ABAC logic already present

Deliverable: a short inventory list with file paths and what they contain:
- Models/schema files
- API endpoints/services
- UI routes/pages/components

---

## Step 2 — Define the MVP Feature Scope
Using what exists today, define an MVP that includes:

### A) Team Overview Page (Read View)
A page that shows:
- Project Owner (single)
- Stakeholders (list)
- Team Members (list)
- Each person row/card shows:
  - name/avatar
  - project role(s)
  - assigned tasks count (optional if already supported)
  - last activity (optional if already supported)

### B) Team Management Controls (Edit View)
Users with permission can:
- Set/replace **Project Owner**
- Add/remove **Stakeholders**
- Add/remove **Team Members**
- Assign project roles to team members (if role system exists; otherwise define minimal structure)

### C) Task Role Awareness (Critical)
Determine if tasks currently support an assigned role:
- If yes: document where it lives and how it is used
- If no: define the minimal data additions needed so tasks can have:
  - `assignedRoleId` (or equivalent)
  - optional `requiredRole` behavior (for prefill logic)

### D) Prefill / Recommendation Logic (MVP)
Define MVP behavior:
- When a task has an assigned role, and there is at least one team member with that role:
  - the assignee picker should default to those people
  - optionally auto-select if only one match exists
- If no match exists:
  - allow manual assignment
  - show a warning: “No team member currently assigned to this role.”

---

## Step 3 — Data Model + API Contract (Minimal Additions)
Based on the codebase findings:
- Confirm what already exists
- Define minimal additions if needed:
  - project owner reference
  - stakeholder list relationship
  - team membership relationship
  - per-project role assignments
  - task assigned role field

Deliverable:
- The minimal set of data objects and relationships
- The API endpoints/actions required (read + update)
- Any necessary permission rules

---

## Step 4 — UI/UX MVP Definition
Specify the MVP UI structure:

### Team Overview Page Layout
- Header: “Team”
- Sections:
  1) Owner (single selector)
  2) Stakeholders (multi selector)
  3) Team Members (table or card list)
- Team Members list columns:
  - Person
  - Project Role(s)
  - Task Role Coverage (optional)
  - Actions (remove, change role)

### Role Mapping UI
- A clear way to assign one or more project roles to a user
- Should support searching and selecting users
- Should not require leaving the page

### Empty States
- No owner assigned
- No stakeholders added
- No team members yet
- Task roles exist but no role mappings exist

- Specify backend changes only if required
- Specify migrations only if required
